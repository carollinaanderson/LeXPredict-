# 04 · Machine learning, end to end

## 1. Frame the problem before choosing an algorithm

| Task | Target | Business decision it supports | Model family |
|---|---|---|---|
| Regression | `claim_value` (BRL) | estimate exposure / provisioning for a new case | decision tree, random forest, gradient boosting, embedding MLP |
| Classification | `unfavorable` (0/1) | prioritise cases, settle vs litigate | same, with probabilities |
| Anomaly detection (unsupervised) | none | review queue for odd claims | Isolation Forest on log value and peer z-score |

Binary label: `Procedente` and `Parcialmente procedente` = unfavorable to the defendant; `Improcedente`
and `Extinção sem resolução de mérito` = favorable (constants in `db.py`; **confirm this mapping with the business**).

## 2. Leakage: the most expensive mistake in ML

| Type | Definition | How it appears | Defence here |
|---|---|---|---|
| Target leakage | a feature contains the answer | a field filled in after the ruling | features only from cases decided **before** the filing date (`03_abt.sql`) |
| Temporal leakage | training on the future | random train/test split on time-ordered data | `temporal_split`: train on the past, test on the future |
| Label-timing leakage | training label not yet known at the cutoff | a case filed before cutoff but decided after it | `purge=True` drops those training rows (classification) |
| Preprocessing leakage | fitting encoders/scalers on all data | target encoding computed globally | encoders live inside the `Pipeline`, refitted per CV fold |
| Identifier leakage | row ids let the model memorise | one-hot of a per-case key | `id_like_columns`, no id in `FEATURES` |
| Tuning leakage | choosing hyper-parameters on the test set | trying settings until test MAE looks good | `RandomizedSearchCV` on train with `TimeSeriesSplit`; test used once |

## 3. Validation design

```
|------------- train (past) -------------||-- test (future) --|
  CV fold 1: [train][val]
  CV fold 2: [-- train --][val]            TimeSeriesSplit: validation always after training
  CV fold 3: [---- train ----][val]
```
Model choice = best **CV** score on train. The test score is reported once, with a bootstrap 95% CI.

## 4. Baselines and metrics

| Metric | Reads as | Use |
|---|---|---|
| MAE (BRL) | "typically off by X reais" | headline for management |
| Median AE | typical error, ignores outliers | complements MAE on skewed money |
| RMSLE | relative error | when 10% off matters equally at 500 and 50,000 |
| MdAPE | median percent error | one number everyone understands |
| R² | share of variance explained | context only; fragile on skewed targets |
| ROC-AUC | ranking quality, 0.5 = coin flip | classifier ranking |
| PR-AUC | quality on the positive class | compare with the base rate (0.39), not 0.5 |
| Brier | probability calibration | needed if you quote probabilities |
| Accuracy | share correct | only next to the majority-class rate (60.8%) |

## 5. Results on the synthetic data (read them like a professional)

**Regression** (test period, 95% CI of the best model's MAE: 3,234 to 3,558)

| Model | CV MAE | Test MAE | Test MdAPE | RMSLE | R² |
|---|---|---|---|---|---|
| dummy (median) | 4,910 | 4,910 | 0.59 | 1.005 | -0.09 |
| decision tree | 3,384 | 3,398 | 0.39 | 0.607 | 0.38 |
| hist. gradient boosting | 3,369 | 3,397 | 0.39 | 0.606 | 0.37 |
| **random forest** | **3,365** | **3,395** | **0.39** | **0.607** | **0.38** |

**Classification** (best model's ROC-AUC 95% CI: 0.665 to 0.698; base rate 0.392)

| Model | CV AUC | Test AUC | Test PR-AUC | Accuracy |
|---|---|---|---|---|
| dummy (prior) | 0.500 | 0.500 | 0.392 | 0.608 |
| decision tree | 0.682 | 0.676 | 0.540 | 0.647 |
| **random forest** | **0.684** | **0.681** | **0.566** | **0.655** |
| hist. gradient boosting | 0.671 | 0.684 | 0.561 | 0.659 |

How to read this:

* All three tree models beat the dummy by about 30% on MAE, but are **statistically indistinguishable
  from each other** (differences far smaller than the CI). Choose the simplest/most explainable (a pruned tree) unless a gain
  is proven. Winning by 3 reais on 3,395 is noise.
* R² of 0.38 is *not* a failure: the data generator adds large irreducible noise. On real data you do not
  know the noise ceiling, which is why the dummy comparison matters.
* Classification AUC of 0.68 is modest. Useful for ranking, not for automated decisions.
* Permutation importance (`reports/*_importance.csv`) is dominated by `judge_id`. It carries judge **and**
  location (nested). It says "the model uses this column", not "judges cause this".

## 6. Overfitting diagnosis

The original project reported train MAE 1.84 and test MAE about 154: a gap of nearly two orders of magnitude.

| Symptom | Diagnosis | Fix |
|---|---|---|
| train error tiny, test error large | high variance (memorisation) | limit depth / leaves, `min_samples_leaf`, ensembles, remove identifiers |
| both errors large | high bias | richer features, more capable model |
| CV score much worse than the train score | optimistic training fit | trust CV, not train |
| CV and test disagree | distribution shift or leakage in CV | check the temporal design |

Regularisation here: `max_depth`, `min_samples_leaf`, `l2_regularization`, smoothed target encoding.

## 7. Encoding categorical variables

| Method | Good for | Weakness |
|---|---|---|
| Integer code per name (original) | nothing | invents an order; trees split on meaningless thresholds |
| One-hot | few levels (UF, vara) | explodes with high cardinality |
| Target encoding (smoothed, cross-fitted) | many levels (judge, comarca) | leakage if done outside CV; shrinks rare levels to the mean |
| Embeddings (`dl.py`) | very many levels, shared structure | needs more data and tuning |

## 8. Deep learning: when and why

`dl.py` is an embedding MLP (PyTorch): categorical ids get learned vectors, numeric features are
standardised with train statistics, early stopping uses the latest 15% of the training period.
**Honest guidance:** on small tabular data, gradient boosting usually matches or beats a neural net. Use DL when you
have text, images, very high-cardinality ids, or multi-task targets. The module is included to demonstrate the
technique; it could not be executed in the authoring environment (PyTorch install did not fit), so run
`pytest tests/test_dl.py` after `pip install -e ".[dl]"` before relying on it.

## 9. Explainability, error analysis, fairness

* Permutation importance (model-agnostic); partial dependence / SHAP are the next step.
* `slice_report` shows error by UF: a model good on average can be poor in one state.
* Profiling individual judges is sensitive: see `docs/LGPD.md`. Prefer court-level features if the use case allows.

## 10. MLOps: what makes it production-grade

| Practice | Implementation |
|---|---|
| Experiment tracking | MLflow params, metrics, data fingerprint, git sha |
| Reproducibility | seeds, pinned minimum versions, metadata JSON with library versions |
| CI | lint, tests (leakage, anonymization, API), end-to-end smoke run |
| Packaging | Dockerfile, non-root, model mounted not baked in |
| Serving | FastAPI, API key, input validation, 503 when unconfigured |
| Monitoring (next) | drift (PSI on features), error vs outcomes as labels arrive, calibration |
| Retraining trigger | drift or error above threshold, or monthly; promote only if it beats the champion on the same test window |
| Rollback | keep the previous artefact + metadata |
| Security | `joblib` loads execute code: only load artefacts you produced |

## 11. Lessons from the original code

| Original | Problem | Now |
|---|---|---|
| Features were `PJ` (case key) and `ID` after `get_dummies` | identifier encoding enables memorisation; train and test encoded separately gives mismatched columns | no ids; encoders inside the Pipeline |
| Judge name -> integer `ID` as numeric feature | arbitrary order treated as magnitude | smoothed target encoding |
| Random `train_test_split` | future leaks into training | temporal split + purge |
| Hyper-parameters picked by eyeballing validation MAE (500...855 leaves) | optimistic estimate | CV on train, test once |
| One metric (MAE), no baseline, no CI | cannot judge value | dummy, five metrics, bootstrap CI |
| Results table used `ID: X_test.index`, then merged judge names on that column | joined row positions to judge ids | ids carried through the pipeline |
| Windows paths with a username in code | leaks identity, not portable | `.env` and `Settings` |
| Merge/filter block pasted three times | drift between copies | functions + tests |
| Model file named only by leaf count | no provenance | metadata JSON, fingerprint, MLflow |
| "accuracy 0.365" printed for a regressor | most likely R² mislabelled | explicit metric names |
